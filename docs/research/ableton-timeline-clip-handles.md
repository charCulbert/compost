# Timeline clip edges and loops: Ableton Live 12 and Bitwig Studio

Research date: 2026-08-27. Sources are the Ableton Live 12 Reference Manual and
the Bitwig Studio User Guide. `Documented` means the linked manual says it
explicitly. `Inference` is a proposed Compost interaction; it is not a claim
about either DAW's implementation.

## Behavior comparison

The Compost column describes the current working tree snapshot, not a new
product requirement. The relevant implementation is
`src/components/compost-timeline.js`; the public timeline contract is also
described in `README.md`.

| Decision | Ableton Live 12 — documented | Bitwig Studio — documented | Current Compost snapshot | Compost recommendation (inference) |
| --- | --- | --- | --- | --- |
| Move versus content body | Arrangement clips move by dragging the clip; **only the clip bar is draggable**, not the waveform/MIDI display. Clicking a clip selects it; dragging in the display selects time. ([Arrangement View](https://www.ableton.com/en/live-manual/12/arrangement-view/), §§6.7, 6.9) | The Pointer tool selects/moves objects and dragging a clip moves it. Clicking below an Arranger clip header commonly invokes time selection; a modifier-drag over the top half of a waveform slides content. ([Arrange View](https://www.bitwig.com/userguide/latest/the_arrange_view_and_tracks/), [Arranger Clips](https://www.bitwig.com/userguide/latest/arranger_clips_and_the_browser_panel/)) | A normal `.clip` is a move/trim target across its box. In automation view, clips are inert and the name strip remains the clip-selection/menu surface. | Make the semantic zones explicit: clip name/bar for object selection, move and context; body for time selection or automation. If whole-body move remains a Compost option, expose it as a deliberate mode/modifier so it cannot steal time selection. |
| Trim, fade and handle zones | Dragging either clip edge changes clip length. Audio fade controls are edge handles that appear on hover when the track is tall enough; the manual calls them small squares and separately names fade-start, fade-end and curve handles. It does **not** specify a pixel hit-box or a clip-edge cursor. ([Arrangement View](https://www.ableton.com/en/live-manual/12/arrangement-view/), §§6.7–6.8) | Trim is documented at the top-right edge with a half-bracket cursor. Audio fades use a white triangle at the middle of an edge; the top half of a waveform is also a content-slide surface with a modifier. ([Arranger Clips](https://www.bitwig.com/userguide/latest/arranger_clips_and_the_browser_panel/)) | Both left/right edges use a fixed em-based trim band (`.4em` mouse, `.75em` touch) and `ew-resize`; there is no separate clip-loop edge band or fade-handle gesture. | Keep separate left/right trim bands. If per-clip loop extension is interactive, reserve a non-overlapping lower-right loop band; reserve a distinct audio-fade band only when fades are actually supported. Measure the geometry in tests. Treat cursor styling as an affordance, not as an Ableton requirement. |
| One-shot extension | Clip View says an unlooped clip plays from its start point to its end point or until stopped. Arrangement edge drag changes the clip length. The manual separately says a consolidated MIDI clip's edges can create more repetitions, so that statement is clip/state-specific rather than a general rule for every one-shot. ([Clip View](https://www.ableton.com/en/live-manual/12/clip-view/), §8.2.1; [Arrangement View](https://www.ableton.com/en/live-manual/12/arrangement-view/), §6.13) | With `Loop` off, an Arranger clip plays once; if its duration exceeds its contents, the later part is empty. ([Inspector: Arranger Clips](https://www.bitwig.com/userguide/latest/the_inspector_panel_on_arranger_clips/), “Loop Section”) | `loop === false` suppresses pass lines and repeats; edge drag changes `length` and does not toggle looping. | Model arrangement `length` separately from source `duration`, `offset` and `loop`. Extending a one-shot must not synthesize repeats or silently enable looping; any beyond-content tail is empty/silent. |
| Per-clip looping | The Clip Loop toggle enables looping, with a loop region defined by position/length. The loop brace's start/end markers can be dragged; playback still begins at the clip start marker, so a clip can run into the loop. ([Clip View](https://www.ableton.com/en/live-manual/12/clip-view/), §§8.2.1, 8.8–8.9) | Dragging the bottom-right edge with the half-bracket/loop-oval cursor creates additional copies after the full length. The dashed first-repeat marker and dotted later markers show repetitions; dragging the first marker changes loop length without changing the clip's total length. ([Arranger Clips](https://www.bitwig.com/userguide/latest/arranger_clips_and_the_browser_panel/)) | Loop pass lines are rendered from `duration`/`offset`, but clip edges have only trim behavior. | Keep a visible distinction between trimming the arrangement extent and changing a clip's loop region. Implement the Bitwig-style loop handle only if it has an explicit event and model field; otherwise do not imply that an edge drag loops. |
| Arrangement/global loop | The Arrangement Loop toggle repeats a song region. If nothing is selected, the brace covers the whole Arrangement; dragging an edge changes start/end, while dragging the bar moves it without changing length. Its context menu can make playback start at the loop start. ([Arrangement View](https://www.ableton.com/en/live-manual/12/arrangement-view/), §6.6) | The Arranger Loop Selector sets the region looped during playback and affects all tracks. Its center moves it and its edges resize it; Bitwig explicitly calls this a playback function, distinct from clip looping as an arrangement function. ([Playing Back the Arranger](https://www.bitwig.com/userguide/latest/playing_back_the_arranger/)) | Ruler loop handles and clip loop pass lines are already separate surfaces/state. | Preserve two independent concepts: global arrangement loop (`start`, `end`, enabled) and per-clip loop (`loop`, source region). Give the ruler center and endpoints distinct hit zones and never infer one from the other. |
| Selection and time tool | Clicking a clip selects it; clicking the background places an insert marker; dragging selects a time span; dragging inside waveform/MIDI selects time within a clip; clicking the loop brace selects loop contents. ([Arrangement View](https://www.ableton.com/en/live-manual/12/arrangement-view/), §6.9) | Pointer selects/moves objects; Time Selection chooses an arbitrary time span. Pointer smart-switches based on hover, and clicking below a clip header commonly selects time. ([Arrange View](https://www.bitwig.com/userguide/latest/the_arrange_view_and_tracks/), [Precise Editing: Clips](https://www.bitwig.com/userguide/latest/precise_editing_clips/)) | Lane background makes time selections; clip gestures select/move/trim; automation overlay owns the body while the name strip still selects the clip. | Keep `clip-select`, `time-select`, `clip-move` and `clip-trim` semantically distinct. Use the clip strip for object actions and the body/empty lane for time selection unless an explicit editing mode owns it. |
| Automation over clips | Automation Mode shows envelopes on top of the audio waveform/MIDI display. An envelope can move into its own lane; Lock Envelopes decides whether clip moves carry automation or leave it at the song position. Arrangement clips receive automation through track automation lanes, not Clip View's automation toggle. ([Automation and Editing Envelopes](https://www.ableton.com/en/live-manual/12/automation-and-editing-envelopes/), §§25.5, 25.5.6; [Clip Envelopes](https://www.ableton.com/en/live-manual/12/clip-envelopes/), §26.1) | Track automation lanes show faint clip content as non-editable context; clip automation can be shown at the bottom of a clip. Automation Follow controls whether track automation moves with clips, while clip editing can make automation repeat with clip content. ([Automation](https://www.bitwig.com/userguide/latest/automation/), [Automation Editor](https://www.bitwig.com/userguide/latest/the_automation_editor_panel/)) | The `automation` attribute overlays one curve over dimmed clips; clip body belongs to the curve, name strip remains the clip surface. Compost never moves automation automatically with a clip. | Keep overlay priority exactly explicit: automation owns the body, the strip owns clip selection/menu. Preserve state-in/intent-out and leave automation-follow/persistence policy to the host; do not silently move lane points on `clip-move`. |
| Snapping | The cursor snaps to the editing grid. Clips also snap to other clip edges, locators and time-signature changes; `Alt`/`Cmd` bypasses snapping. ([Arrangement View](https://www.ableton.com/en/live-manual/12/arrangement-view/), §§6.7, 6.10) | Grid, Grid Offset and Events are independent snap anchors; the settings apply to all editing actions, and `Shift` temporarily inverts the current snap setting. ([Arranger Clips](https://www.bitwig.com/userguide/latest/arranger_clips_and_the_browser_panel/)) | Snap mode is view-time and `Cmd`/`Ctrl` inverts it; anchors include clip edges, locators and global loop bounds, with an 8px reach. | Keep full-precision model values and snap only the gesture preview/commit. Continue using explicit anchors and modifier inversion; do not bake the display grid into clip data. |
| Zoom and navigation | The Overview and beat-time ruler scroll/zoom by drag; `+`/`-`, modifier-wheel, `Z`/`X`, pinch and Follow are documented. ([Arrangement View](https://www.ableton.com/en/live-manual/12/arrangement-view/), §§6.1–6.2) | The Beat Ruler becomes a magnifying glass in zoom mode; vertical drag zooms, horizontal drag scrolls; `+`/`-`, modifier-drag, middle-button drag, pinch and follow modes are documented. ([Arrange View](https://www.bitwig.com/userguide/latest/the_arrange_view_and_tracks/)) | Zoom is bounded (`4–480` px/beat), supports pinch, and keeps a beat anchor during pinch. | Preserve the zoom anchor and bounded scale. Use cursor changes where they clarify a mode, but do not copy undocumented Ableton cursor semantics; verify ruler/clip hit geometry at narrow and wide zooms. |

## Normative Compost recommendation

1. Treat `start`, `length`, `duration`, `offset` and `loop` as separate state. A one-shot edge drag changes only its visible/arrangement extent; a looping extension repeats only when `loop` is already enabled.
2. Hit-test in priority order: interactive ruler, automation body (when shown), optional lower-right clip-loop band, left/right clip-trim bands, then the clip strip/body's selection behavior. Trim and loop bands must not overlap.
3. Use `ew-resize` (or an equivalent explicit affordance) for trim and a separate loop affordance for loop extension. Ableton's manual does not define a cursor or pixel hit-box; Bitwig's named cursor shapes are useful UI precedent, not an Ableton requirement.
4. Keep global Arrangement looping independent from per-clip looping. Emit semantic Compost intents and let the host decide automation following, persistence and playback policy.
5. Add geometry tests for each band at multiple zooms and track heights; screenshots alone cannot prove which gesture wins.
